SQL을 보기 좋게 정리해야 하는 이유

압축된 쿼리 한 줄, 리뷰할 때마다 눈이 아팠다면 이 글이 도움이 됩니다.

ORM이나 데이터베이스 도구, 로그는 SQL 쿼리를 사람이 읽기 좋은 형태가 아니라 한 줄로 압축해 출력하는 경우가 많습니다. SELECT, FROM, WHERE, JOIN 같은 절이 공백 하나만으로 이어져 있으면, 쿼리가 정확히 어떤 조건으로 어떤 테이블을 조회하는지 한눈에 파악하기 어렵습니다.

키워드 대문자화와 줄바꿈의 역할

SELECT, FROM, WHERE 같은 SQL 키워드를 대문자로 쓰는 것은 흔한 관례입니다. 키워드가 대문자이면 테이블명이나 컬럼명 같은 실제 데이터와 시각적으로 구분되어 눈이 훨씬 빠르게 구조를 따라갈 수 있습니다. 또한 절마다 줄을 바꾸면 쿼리의 논리적 흐름이 코드처럼 한눈에 보입니다.

정리할 때 흔히 놓치는 것

쿼리 끝의 세미콜론, 짝이 맞는 따옴표와 괄호, 서브쿼리의 들여쓰기는 손으로 직접 정리할 때 가장 놓치기 쉬운 부분입니다. 특히 조건절 안에 서브쿼리가 여러 겹 있으면 괄호 개수를 맞추는 것만으로도 시간이 오래 걸립니다.

포맷터가 도움이 되는 이유

SQL 포맷터는 키워드 대문자화와 절 단위 줄바꿈을 일관되게 적용하고, 끝에 세미콜론이 없으면 자동으로 채워줍니다. 특정 데이터베이스 방언에 종속되지 않고 SELECT, INSERT, UPDATE 같은 공통 구조를 기준으로 정리하므로, 리뷰어가 쿼리를 훨씬 빠르게 훑어볼 수 있습니다.

자주 묻는 질문

포맷터가 SQL을 실행해서 검증도 해주나요?

아니요. 브라우저 안에서 텍스트 구조만 정리할 뿐 쿼리를 실행하거나 데이터베이스에 연결하지 않습니다. 실제로 실행 가능한 쿼리인지는 별도로 확인해야 합니다.

어떤 데이터베이스에서도 그대로 쓸 수 있는 형식인가요?

SELECT, INSERT, UPDATE 같은 표준 SQL 구조를 기준으로 정리하므로 대부분의 데이터베이스에서 무리 없이 통용됩니다. 다만 특정 DB 전용 문법(예: 백틱, 특수 연산자)까지 완벽히 대응하지는 않으므로, 방언이 강한 쿼리는 결과를 한 번 확인하는 것이 좋습니다.
